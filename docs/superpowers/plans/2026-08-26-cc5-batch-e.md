> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the five-job `FailureDetector` god class along its existing seams — timing policy, target-selection policy, and the ×5 probe-lifecycle choreography — while closing the naming fossils, dead surface, and annotation gaps the audit assigns to this batch (CC5-2, 3, 14, 46, 47 + the Batch A-routed doc/clamp items and the D-follow-up's attribution-pin input).

**Architecture:** Behavior-preserving extraction. Two new domain services (`ProbeTimingPolicy`, `ProbeTargetSelector`) absorb jobs (b) and (d) of CC5-2; the detector keeps protocol orchestration, SWIM roles, and transport plumbing. The probe lifecycle collapses from five hand-written copies to two named helpers (`_pingExchange` for the immediate-cleanup sites, `_probe` for the direct+indirect+late-Ack choreography). The existing 10-file detector test suite is the net: **no assertion may change** except mechanical rename updates; suite count may drop only by deletions of tests whose entire subject is deleted surface, each with a coverage argument.

**Tech Stack:** Pure Dart (`packages/gossip`), `dart test`/`analyze`/`format`, melos gates.

**Spec:** `docs/audits/2026-08-23-clean-code-audit.md` CC5-2 (:62-65), CC5-3 (:67-70), CC5-14 (:100), CC5-42 clamp clause (:141), CC5-43 (:142), CC5-46 (:145), CC5-47 (:146) + Batch A outcome record item "Batch E additionally owns" (campaign plan :223) + the D-follow-up input in the CC5 resume-state memory (transport-error pin attribution).

## Design decisions (pre-filled; binding unless Joel vetoes)

- **ED1 — no new `ProbeScheduler`.** The audit's fix direction predates Batch B: the scheduling *mechanism* already lives in the shared `GenerationScheduler` (constructor wiring, ~25 lines, stays in the detector). What remains of job (a) — pacer + interval formula — moves with the timing policy (ED2). The addendum records this deviation and why.
- **ED2 — `ProbeTimingPolicy` in `lib/src/membership/domain/services/probe_timing_policy.dart`.** Owns: static-override semantics as nullable `Duration?` fields (closing CC5-13's detector slice — the dead `?? 500ms`/`?? 1000ms` defaults that are never read unless the flag is set are deleted, the flag pairs go with them), the RTT-derived timeout math (`effectivePingTimeout`, `effectivePingTimeoutForPeer`), the interval formula + `QuiescencePacer` (with `news()`/`quietRound()` forwarders), and the timing constants (`_minPingTimeout`, `_maxPingTimeout`, `_minProbeInterval`, `_maxProbeInterval`, `_probeIntervalMultiplier`). Consumes `RttTracker` and `PeerRegistry` (for per-peer estimates). The detector keeps thin delegating getters (`effectivePingTimeout`, `effectiveProbeInterval` — Coordinator reads both).
- **ED3 — `ProbeTargetSelector` in `lib/src/membership/domain/services/probe_target_selector.dart`.** Owns: the shuffled round-robin order + cursor, probing holds, the last-probe-attempt suppression-cap map, the unreachable round-robin index, intermediary selection, and the whole eligibility policy (holds, freshness suppression, `_maxProbeSuppression` cap — the constant moves here). Consumes `PeerRegistry`, `TimePort`, `Random`; the freshness window (`effectiveProbeInterval`) is passed per call so the selector does not depend back on timing. The detector keeps thin public delegates for the Coordinator-facing hold API (`setProbingHold`, `clearProbingHold`, `hasProbingHold`, `forgetPeer`).
- **ED4 — CC5-3 lands as two detector-private helpers, not one.** `_pingExchange({required NodeId target, required Duration timeout, bool allowForwarded = false, required Future<void> Function(int sequence) send})` owns allocate→track→send→await→cleanup for the three immediate-cleanup sites (`probeNewPeer`, `_performIndirectPing`, `_handlePingReq`). `_probe(NodeId target)` owns the full direct+indirect choreography for `performProbeRound` and `_probeUnreachablePeer`, returning `enum _ProbeOutcome { aliveDirect, aliveIndirect, aliveLateDirect, failed }` so both callers keep their exact per-outcome policies (logging, contact recording, pacer signals). The direct leg's pending deliberately stays alive through the indirect phase (late-Ack grace) — its try/finally is written out once inside `_probe` with a comment saying exactly that. Net: the lifecycle appears twice, once per cleanup discipline, instead of five times.
- **ED5 — renames.** Selector method: `nextProbeTarget()` (per CC5-14; the old name was wrong twice — not random, not only reachable). Detector command: `checkPeerHealth` → `updatePeerHealth` (CC5-46: state-transitioning command named as a query). Engine's dead `selectRandomPeer` (gossip_engine.dart:1179-1181) deleted with its two keeping-alive tests (gossip_engine_test.dart:60-80) — coverage argument: it delegates 1:1 to `PeerDirectory.selectRandomPartner`, which has its own suite (verify; if not, move the two tests to the directory's suite instead of deleting).
- **ED6 — one clamp.** New `Duration clampDuration(Duration value, {required Duration min, required Duration max})` in `lib/src/shared/domain/services/duration_clamp.dart` (TDD). `RttTracker`'s private `_minSample`/`_maxSample` become public `static const minSample`/`maxSample` — the single source; the detector's mirrored `_minRttSample`/`_maxRttSample` are deleted in favor of references. All three clamp styles (nested ternary in the interval formula, if-chain in `_recordRtt`, `RttTracker._clampSample`) become `clampDuration` calls.
- **ED7 — CC5-46 satellites, exact dispositions.** `registerMaterializer` returns `Future<void>` (doc-admitted always-empty list; callers verified/updated). `Coordinator._`'s required always-null `gossipEngine`/`failureDetector` parameters removed. `VersionVector.set`/`increment` and `RttTracker.reset` deleted (production-dead public kernel members; their tests deleted with the deleted-surface argument, except any that also pin surviving behavior — those are retargeted). `FoldCursor` const constructor gains `assert((author == null) == (sequence == null), …)` (red test first: mixed construction must throw in checked mode). `resetState` gains the same `hasStream` guard `getState` has (red test first); `getStateStream` is synchronous and cannot await `hasStream` — if parity is impossible without an API change, document the asymmetry at the declaration with the why, and report it.
- **ED8 — `@visibleForTesting` only after a grep proves test-only.** Candidates: `handlePing`, `handleAck`, `recordProbeFailure`, `updatePeerHealth`, `performProbeRound`, `hasProbingHold` — each annotated only if `lib/` has no caller outside the detector (Coordinator verified to use: start/stop/startListening/stopListening/setProbingHold/clearProbingHold/forgetPeer/probeNewPeer/effectivePingTimeout/effectiveProbeInterval/rttTracker/timePort). `PeerMetrics` gains `@immutable` and a `copyWith`; the three hand-copied 7-field constructions collapse onto it.
- **ED9 — the D-follow-up attribution pin is attempted, with an escape hatch.** After the extraction, strengthen the lifecycle transport-error test to pin BOTH emissions (engine's and detector's) if they are distinguishable and stable; if they are byte-identical in type+message shape, record why the pin is inexpressible and leave the single-emission pin as-is.
