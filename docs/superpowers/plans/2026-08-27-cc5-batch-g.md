## Design decisions (pre-filled; binding unless Joel vetoes)

- **DG1 — `holdProbing(NodeId, Duration)` is the public hold API; `setProbingHold` becomes `@visibleForTesting`.** The detector computes the deadline from its own clock. The coordinator never reads `detector.timePort` again (that was its only read — verified). Tests keep using `setProbingHold` unchanged (absolute-deadline control is exactly what tests need).
- **DG2 — two snapshots, composed by the facade.** `FailureDetector.timingSnapshot()` returns a small membership-owned record/class carrying: per-peer RTT map, the min-SRTT selection with its PAIRED variance, sample count, has-samples, effectivePingTimeout, effectiveProbeInterval, and the global-tracker fallback applied INTERNALLY (the detector owns both the registry and the tracker — the fallback rule is its policy). `GossipEngine` exposes `int get transportBacklog` (its port's `totalPendingSendCount`) beside the existing `effectiveGossipInterval`. `Coordinator.getAdaptiveTimingStatus` becomes pure assembly of the two, `AdaptiveTimingStatus`'s exported shape and semantics byte-compatible.
- **DG3 — `ChannelRemoved` emits from `ChannelService.removeChannel` via the same `onEvent` path as `ChannelCreated`.** The coordinator's manual construction is deleted. This MOVES the emission earlier (inside the service call, before the facade-cache cleanup and engine `setChannels`) — analyzed as observable-ordering change; accepted if no test pins the late ordering, recorded either way.
- **DG4 — the facades' `channelService` field goes private** (`_service`), constructor takes it under a non-field-public name; `@internal` rejected as the weaker fix since zero readers exist (repo + OpenDoorApp verified). CHANGELOG "Breaking — API surface" line (the field was public on exported types).
