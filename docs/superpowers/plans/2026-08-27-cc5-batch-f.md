- **DF1 — D3 renames, all three surfaces, hard.** Engine `maxDeltaResponseBytes` → `maxMessageBytes` (D3: internal, hard). `CoordinatorConfig.maxDeltaResponseBytes` → `maxMessageBytes` too (public; zero consumers set it — verified; CHANGELOG-recorded; leaving the public field under the narrow name while the engine renames would preserve CC5-12's lie at its most visible home). `Coordinator.create(timerPort:)` → `timePort:` (public, hard per D3; OpenDoorApp passes it — CHANGELOG-recorded, migration pre-accepted). Error-message text that embeds the old name (`'cannot fit maxDeltaResponseBytes=…'`) updates with the rename — this is the ONE sanctioned message-text change in the batch, listed in the report with the tests it touches.
- **DF2 — placement by dependency reality.** `sync/domain/services/`: `gossip_timing_policy.dart` (deps: PeerDirectory, QuiescencePacer, clampDuration), `pending_pull_tracker.dart` (deps: TimePort, RttTracker). `sync/application/`: `digest_budgeter.dart` (needs `SyncMessageCodec` sizing), `reactive_pusher.dart` (debounce state machine; flush action injected), `delta_merger.dart` (orchestrates EntryRepository/HlcClock/LocalNodeRepository — use-case logic).
- **DF3 — CC5-13 engine slice: the field triad collapses INSIDE the timing policy.** The engine's `_adaptiveTimingEnabled` + `_staticGossipInterval` + `_staticIntervalProvided` puzzle becomes an internal sealed representation in `GossipTimingPolicy` (`_StaticInterval(duration)` / `_Adaptive()`), constructed from the engine's UNCHANGED `gossipInterval`/`adaptiveTimingEnabled` constructor params. Resolution semantics preserved exactly: explicit static wins; else adaptive-if-enabled (pacer applies here only); else the 500 ms default static.
- **DF4 — the pusher is a debounce state machine; the flush action stays in the engine.** `ReactivePusher` owns buffer + flag + generation + debounce timer + the stale/failure discipline (including C6's wedge fix and D7's stale-late-failure semantics, both test-pinned). It takes injected `isRunning`, `flush(batches)`, and `onSchedulingFailure(error, st)` callbacks; the engine keeps `_flushPendingPushes` (partners + budget check + send) and the error formatting. The engine's round-loop `onSchedulingError` calls `pusher.onRoundLoopDead()` exactly where it bumps today (gated on `!_scheduler.isRunning`) — the long why-comment at engine :374-400 moves with the call, split between the two homes without losing a clause.
- **DF5 — the merger owns the merge pipeline end-to-end; the tracker stays outside it.** `DeltaMerger.merge(response, {required bool solicited})` owns: KeyedTaskChain serialization, solicited-floor adoption, contiguity selection + gap reporting/dedup (`_reportedGaps` moves here), HLC update + fire-and-forget persistence, `appendAll`, out-of-order detection, `onEntriesMerged`, and building the continuation `DeltaRequest`. The ENGINE keeps: pending-key completion + RTT sampling (via the tracker) BEFORE calling merge, `_mergedBatchCount`/`_recordNews` on the merger's reported outcome, and re-marking pending for the continuation. The merger reports `({DeltaRequest? continuation, bool mergedNewEntries})`.
- **DF6 — budgeter reports diagnostics, engine formats errors.** `DigestBudgeter.fitRequest`/`fitResponse` return `(digests, diagnostics)` where each diagnostic carries (channel, streamId, cost); the engine renders today's exact `ChannelSyncError` text. Both rotation cursors live inside the budgeter.
- **DF7 — CC5-10/11 are engine-internal decompositions, zero test diffs** (E4's rule): `_onDigestRequest`/`_onDigestResponse`/`_onDeltaRequest`/`_onDeltaResponse` extracted from the dispatch; `_computeDeltaRequests`'s per-stream body → `_evaluateStreamDigest`, with the self-contained authorship-floor block (:1446-1465) → `_adoptClaimedAuthorshipFloor`.
- **DF8 — CHANGELOG discipline.** F1 appends the rename entries to the Unreleased section; F8 verifies nothing else in the batch is consumer-visible (extraction is internal).
