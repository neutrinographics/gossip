# CC5 Batch C — Error-Context Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Errors carry accurate context everywhere — decode failures stop masquerading as handler failures and vice versa (CC5-9), the null-repository mode stops emitting false alarms (CC5-19, D1), domain guards throw typed `DomainException` (CC5-23, D2), stack traces reach the log sink and post-dispose errors reach `onLog` (CC5-52) — plus the three items Batch B routed here: the BD3 compaction-retry ruling, the reactive-push wedge, and the out-of-order recovery residual.

**Architecture:** Every behavior change is test-first. The two message loops get a decode-catch / handling-catch split with distinct error types. PeerService's null-repo guards become silent (documented mode). The two local-node guards throw the already-exported `DomainException`, and the weak test matchers that its bare `Exception` forced are strengthened in the same motion. Stack-trace threading extends the detector's bare `_log(String)` to the engine's richer shape. The wedge and OOO fixes are small, pinned corrections in code Batch B just consolidated.

**Tech Stack:** Pure Dart (`packages/gossip`), `dart test`/`analyze`/`format`, melos gates.

**Spec:** `docs/audits/2026-08-23-clean-code-audit.md` CC5-9/19/23/52 + the Batch A and Batch B outcome-record sections (binding: Batch A obliges C to add the `onLog` post-dispose sink before restoring its doc clause; Batch B routes BD3, the push wedge, and the OOO residual here).

## Design decisions (pre-filled; binding unless Joel vetoes)

- **CD1 — BD3 resolved: the compaction loop keeps stop-and-surface on scheduling failure (no retry).** Consistent with both engines' documented policy; a failing `TimePort.delay` is a broken platform timer, and retrying a broken timer spins. The app observes the `StorageSyncError` and can stop/start. Close BD3 by documenting the policy as deliberate on `CoordinatorConfig.compactionInterval`'s doc (one sentence) — no code change.
- **CD2 — stack traces go to the log sink, not into `SyncError`.** Adding a `stackTrace` field to the exported error hierarchy is public API surface this batch doesn't need; `_log`'s optional `(error, stackTrace)` parameters (engine already has them) are the home. The detector's `_log(String)` is extended to match the engine's shape.
- **CD3 — error-type vocabulary for the catch split:** decode failures keep `SyncErrorType.messageCorrupted` with the "Malformed…" message; handling failures become `SyncErrorType.protocolError` with "Failed handling <MessageType> from <sender>: $e". Existing tests that pin `messageCorrupted` for what is actually a handler failure get updated (listed per the constraint above).
- **CD4 — the wedge test's time double:** a small `ScriptedDelayTimePort` (fails the Nth `delay` call) added to `test/support/` — it also down-pays Batch D's late-failure-double need; keep it minimal and documented.
