# Record where the Dart library and its Kotlin twin diverge, with a verdict

**Track:** Kotlin port   **Depends on:** nothing

## What this is

The Dart library (`packages/gossip`) and its standalone Kotlin port
(`gossip-kt`) implement the same protocol twice, in two languages, by two
different hands at two different times. Every time a review of one
compares it against the other, it turns up a place where they made a
different choice — sometimes a deliberate, permanent one, sometimes an
accident nobody has revisited. This file is the durable register of those
differences: one row per divergence, a plain read of where each side
stands, a verdict on which is better (or that the difference is fine to
keep), and where the fix (if any) already lives.

The practice this register exists to support is bidirectional: when a
review of a Dart change surfaces a divergence, or a review of a Kotlin
change does, the divergence gets a row here before the conversation that
found it is forgotten. Adoption can flow either way — most of the time the
port is catching up to the original, but sometimes the port found the
better shape and the original should adopt it.

## Why it matters

Two implementations of one protocol drift apart silently unless someone
writes the drift down. A code review that spots a divergence and doesn't
record it is a fact that evaporates the moment the branch merges — the
next person to touch either side has no way to know the difference was
ever noticed, let alone judged. Recording it with a verdict turns a
one-time observation into something the other library can act on whenever
it's next convenient, and stops the same divergence from being
"rediscovered" and re-litigated in a future review.

## The register

| Divergence | Where each side stands | Which is better | Recommendation |
|---|---|---|---|
| Frame dispatch | kt chains membership→sync through one dispatch point: exactly one report per bad frame, and a `NotMine` result short-circuits before the other codec ever tries to parse. Dart runs both engines' codecs independently over the full incoming stream, so a byte neither codec recognizes throws in both and is reported twice per frame — a known flaw the wire-versioning spec's §5.2 rollout-ordering constraint has to work around rather than fix. | kt | Dart should adopt a single dispatch seam that tries one codec, only falls through to the other on a sibling (`NotMine`)-shaped result, and reports malformed frames exactly once. |
| Decode failure contract | kt's decode result is a sealed type with three cases — decoded, not-mine (sibling family, fall through), and malformed (with diagnostic detail). Dart represents the same three outcomes as: `null` return for "not mine", a thrown exception for an unrecognized type, and an `onError` callback catch at the call site to turn that exception into a report. | kt | kt's shape is more explicit and type-safe — the caller can't forget to handle a case the way it can forget to catch an exception. Candidate for Dart to adopt, most naturally alongside the single-dispatch-seam change above since both touch the same call sites. |
| Frame classifier | kt's frame classifier (`FrameFraming`) is a non-throwing sealed result carrying typed diagnostics for each way a frame can fail to classify. Dart's `frameTypeOffset` throws and otherwise returns a plain offset. | kt is richer | Optional. Dart already adopted the differentiated per-class marker diagnostics this classifier produces (the "unregistered wire version N" style messages); moving to a non-throwing sealed *shape* on top of that is a nice-to-have, not a gap that causes wrong behavior. |
| Version-vector explicit-zero handling | Dart drops explicit zero entries at construction (`VersionVector`'s normalization), on the rationale that keeping them lets structural and semantic equality diverge for what should be the same vector. kt preserves explicit zero entries as written. | Tolerated asymmetry, with one real consequence | Decode is genuinely unaffected: absent and explicit-zero are the same value to both sides. **But encoding is not symmetric, and that has bitten a consumer.** Dart cannot reproduce a frame containing `"node":0`, so a byte-exact comparison of Dart's *output* against a kt-sourced golden vector containing an explicit zero can never pass — found 2026-08-31 while bumping the app's pin, where a translator round-trip test failed for exactly this reason. The fix there was to compare that one direction semantically and to leave the golden untouched, since the golden is truthful about what kt emits. Anything byte-comparing Dart output against kt-captured vectors needs to know this. **Ruled a normalization on the owner's 2026-09-01 exemption review** (reversing "deliberate and likely permanent"): only Dart's side of the asymmetry was ever defended — construction-time zero-dropping keeps structural and semantic equality aligned — while kt's preservation is just the unnormalized original shape, and the asymmetry has already bitten a consumer. kt adopts Dart's normalization; homed as KT-E scope in [the wire campaign](kt-wire-versioning-campaign.md). Existing kt-captured goldens stay untouched (truthful about the deployed artifact); the change lands with fresh vectors. |

Homed at [Drop peer persistence from the Dart library](health-drop-peer-repository.md); also deletes the per-peer write-ordering chain that exists only to serialize these writes. |
| SWIM incarnation/refutation | Dart deliberately implements no incarnation/refutation — its detector documents the decision ("relies on the transport's fast membership oracle and per-contact recovery instead") and no membership message carries an incarnation field in either dialect. kt carries the full machinery anyway: `Peer.incarnation`, `PeerRegistry.incrementIncarnation`/`updatePeerIncarnation` (refutation recovery), a persisted local incarnation on `LocalNodeRepository` restored at `Coordinator.create` — and the server implements the persistence (`PgLocalNodeRepository`). If refutation is ever actually wanted, it is a both-sides feature with a new wire field — dialect-revision material, designed once for both twins, not a resurrection of this scaffolding. |
| Probe marking vs send latency | Both twins judged a stalled record's probe-due-ness twice around a suspending send — shaped with one clock read, marked probed with a later one — so a probe window opening mid-send could be consumed by a request that was SHAPED for the author and cannot elicit the range. kt fixed it in the stalled-range port's review wave (single `shapedAtMs` captured before shaping, reused by `markProbed` inside the one `sendDeltaRequest` seam). Dart still reads `timePort.nowMs` separately in `shapeSince` (engine builder) and `markProbed` (`_sendDeltaRequests`). | kt (now) | **Back-port to Dart**: capture the shaping instant once per request and pass it to `markProbed` — queued as an actionable line in [Sweep the remaining minor audit findings](health-minor-findings-sweep.md). | Unknown-channel digests | Dart emits a `ChannelSyncError` protocolError for every digest naming a channel it hasn't joined — every round, per peer (the 2026-08-31 fleet logs' nineteen-unknown-channels spam is this path, and part of [digest scoping](engine-scope-digests-to-shared-groups.md)'s evidence). kt (stalled-range port, deliberate) trace-logs it instead, the same treatment the merge path gives an unheld stream — which is itself a CONVERGED trace-silent decision on both sides. | kt | Routine mixed-membership traffic is not an error; an error channel that fires every round for a permanent, expected condition trains operators to ignore it. **Dart flow-back candidate**: downgrade to a trace log (or fold into digest scoping, which removes the occurrences at the source). |
| Adaptive interval formula | Was: Dart median SRTT ×2 vs kt MINIMUM SRTT ×2 (one fast peer over-drives slow links). **Converged** by wire-efficiency phase 1 (gossip-kt #6): kt now uses the median, computed from a per-round snapshot so the scheduler's delay callback stays non-suspending. | Dart, converged | **Closed.** The snapshot-refresh shape (one round of staleness, self-correcting) is a documented kt adaptation, not a semantic divergence. |
| Empty-registry probe pacing | BOTH twins skip the quiet-round call when the registry is empty, so a solo node's probe loop never paces toward the 30s ceiling — pointless wakeups on mobile — while the adjacent comment claims the case is quiescence. Found by the kt phase-1 review; verified identical in Dart. | Neither — a SHARED gap | Fix jointly: pace the empty-registry case too (kt's comment now states the divergence honestly; Dart's still doesn't). Small, ride-along candidate for each side's next detector-touching batch. |
| Stale push snapshots vs compaction | Both twins' reactive push flushes buffered entries by value, so an entry compacted between the write and the debounce flush still travels (bounded: receivers' contiguity guard applies; no below-floor-never-travels invariant exists). Found by the kt phase-1 review; Dart shares it. | Neither — a SHARED, bounded gap | Record, don't fix now: re-reading the repository at flush time trades a rare bounded oddity for a hot-path read. Revisit if a floor invariant is ever wanted. |
| Reactive-push invalidate ordering | kt's start() must invalidate the pusher BEFORE opening the running gate, and invalidate() must clear the in-flight flag — a debounce racing a restart on kt's thread pool would otherwise wedge push forever. Dart's single-isolate ordering makes both impossible; its invalidate() deliberately leaves the flag. | Parity of contract, divergent mechanics | Platform-necessitated (the E3 exemption pattern); documented on kt's invalidate(). No Dart action. |
| Delta batching | kt's original (pre-wire-versioning-batch) delta emission batched multiple messages into one envelope. That shape was the inspiration for the budget-aware batch-envelope wire-efficiency item, which already exists on the roadmap. | N/A — idea already captured | Don't duplicate; see [Coalesce wire traffic into fewer radio wakeups](engine-message-coalescing.md) ("batched delta forms"), which carries this forward for both libraries. |
| Entry insertion order | kt's `findInsertIndex` (`in_memory_entry_repository`-equivalent) orders entries by timestamp only when inserting. Dart orders by the full `(timestamp, author, sequence)` total order. | kt is worse | This is a real correctness gap, not a style difference: two peers whose materializers fold entries in different arrival order for an HLC tie will converge to different derived state. The fix is already routed — it's flagged as a KT-E candidate in the Kotlin port's batch sequence (`docs/superpowers/specs/2026-08-28-kt-port-dart-fix-inventory.md`, item 13 / "M3"). This row exists so the divergence has a home outside that plan file too. |
| Pending-request expiry | Dart uses an adaptive expiry window for pending delta requests, scaled between roughly 2 and 30 seconds based on measured round-trip time. kt used a fixed 5-second expiry. | Dart, converged | **Closed** by Batch KT-B (2026-08-29): kt ported the adaptive RFC-6298-style tracker (2–30s window, release-on-send-failure); see `docs/plans/2026-08-29-kt-batch-b-sync-depth.md` in the gossip-kt repository. |
| Merge-path serialization | Dart's `DeltaMerger`/`KeyedTaskChain` protects against an interleaving hazard across concurrent merge suspensions. kt's single-collector receive loop structurally excludes that hazard — one coroutine processes one inbound message at a time — and Batch KT-B (T1) additionally closed the one gap that could have broken the assumption: an unguarded `Coordinator.start()` could double-start the collector and fork the loop; it now has start-idempotence. | Tolerated architectural difference | No action for kt. If Dart ever adopts a single-dispatch receive loop (see the frame-dispatch row above, which is already a candidate for that shape), the `KeyedTaskChain` tax could be reassessed then — not before. |
| `appendAll` phantom-stream registration | Both libraries' `appendAll` called `getOrPut` (stream-map lookup-or-create) before validating the batch, so a batch rejected in full still left behind an empty stream entry — visible to later reads as a stream that was never actually written. kt fixed it in Batch KT-B (`fb0cd32`, T2 fix round): validation now precedes the `getOrPut`. | kt (now) | **Fix in Dart** — this is a real, if minor, bug carried from the shared original shape, not a style choice. Also tracked as an actionable line in [Sweep the remaining minor audit findings](health-minor-findings-sweep.md). |
| Ingestion guard for unheld streams | Dart's `GossipEngine` refuses inbound deltas for a channel/stream it doesn't currently hold (`gossip_engine.dart:1532-1539`). kt lacked this repository-level gate entirely. | Dart, converged | **Closed** — kt converged in Batch KT-B (`fb0cd32`, T2 fix round): it now mirrors Dart's refusal exactly (trace-silent, matching log level). |
| Test-strength flow-backs (three examples) | (1) kt's authorship-floor pin (Batch KT-B, T4) asserts at the allocation level (the actual sequence allocator's output); Dart's equivalent pin asserts only at the mark level. (2) kt's crown integration scenarios (T7) seed an error sink listening from every node from t=0; Dart's per-node late-listen setup can miss errors raised before a listener attaches. (3) kt has a small unit pin for gap-reopening on `clearPendingRequests` (T6 ride-along) that Dart's suite has no equivalent of. | kt, in all three | Adopt kt's stronger versions in Dart's test suites — none of these are behavior changes, only discriminating-power gaps in the pins themselves. |
| Event-dispatch placement | Dart emits domain events in-aggregate (e.g. `PeerRegistry.onEvent`). kt emits them from an application service wrapping the aggregate (`PeerService`) — established when Batch KT-B's PeerDirectory ACL (T5) required rewiring event dispatch through the service layer. | Structural, not a defect | No fix, but record the rule the port surfaced: any kt ACL placed over a service-wrapped aggregate MUST route writes through the service, or event dispatch dies silently — the aggregate's own `onEvent` never fires if a caller reaches the aggregate directly. |
| Thread-safety posture (domain services on a hot/arbitrary-caller boundary) | Dart's single-isolate execution model means no domain service needs internal synchronization (ADR-001). kt's `PendingPullTracker` (Batch KT-B, T6) sits on a boundary where the Coordinator's non-suspend `stop`/`pause`/dispose calls race the receive loop's arbitrary-coroutine calls, with no happens-before between them — it and the matching `_reportedGaps` guard are internally monitor-guarded (plain JVM `synchronized`) rather than deferring to a `Mutex`, which was rejected because it would force suspend-ness onto the otherwise non-suspend facade methods. | N/A — necessitated by the platform | **Recorded rule SUPERSEDED (owner, 2026-09-02):** the default is now a PURE domain class plus a `Synchronized*` wrapper in `infrastructure/` (the peer-registry / stalled-range-registry shape) — locks never live inside domain classes; homed at [Purify the Kotlin domain layer](kt-pure-domain-concurrency.md). | Partition primitive | Dart's test harness (`TestNetwork` DSL) can partition a link one-way or two-way while preserving each side's stale state, closely modeling a real radio dropout. kt's integration tests modelled peer loss via `peers.remove()`/`peers.add()`, which scrubs all state on removal — it could not represent a peer that's unreachable but still believed present. | Dart stronger, **now closed and overtaken** | **Closed** by Batch KT-D (2026-08-30): kt's bus grew directional `blockLink`/`healLink` and `partitionNode`/`healNode`. kt then went further than Dart — see the heal-in-place row below. |
| Per-cycle interval recomputation | Dart's periodic loops recompute their delay every cycle (`GenerationScheduler.nextDelay()` is called fresh before each wait), so adaptive intervals actually adapt while running. kt's gossip loop computes `effectiveGossipInterval()` once at start (`GossipEngine.kt:132`) and `schedulePeriodic` freezes it thereafter — the "adaptive" interval holds its start-time value for the life of the loop. | Dart stronger | Batch KT-C ported `GenerationScheduler` for the auto-compaction loop (2026-08-30); migrating the gossip and failure-detector loops onto it (restoring per-cycle adaptation, mirroring Dart's CC5-7 consolidation) is the follow-up. | nextDelay error uniformity | kt's `GenerationScheduler` invokes `nextDelay()` inside the loop coroutine's try, so a throwing `nextDelay` is uniformly a scheduling error on every cycle. | Channel-level manual compact facade | kt's `Channel.compact()` fans out over every stream in the channel and returns a per-stream result map; Dart exposes only the stream-level `EventStream.compact()`. | kt richer | Candidate Dart flow-back: add a channel-level compact fan-out to Dart's `Channel` facade. | SWIM indirect probing | **Dart works; kt's is inert.** Dart's `FailureDetector` subscribes with `Stream.listen`, which does not await its handler, and Dart runs two independent subscriptions (detector and engine each listen separately) — so an intermediary's `_handlePingReq` can await the target's Ack while the same subscription keeps delivering. kt's `Coordinator.start` collects `messagePort.incoming` in a SINGLE suspending `Flow.collect` (a documented invariant, load-bearing for `GossipEngine`'s unsynchronized merge state); `handlePingReq` is called inside that lambda and suspends in `awaitAckWithTimeout`, but the target's Ack can only arrive through the very collector it is blocking. The intermediary therefore always times out at `INTERMEDIARY_TIMEOUT`, never forwards the Ack, and `cleanupPendingPing` has already dropped the entry by the time a late Ack could match. | Dart — this is a live kt defect, not a style difference | Behavioral consequence: a one-way-deaf pair with a healthy relay keeps both views REACHABLE in Dart but degrades to SUSPECTED in kt — SWIM's indirect-probe path buys kt nothing today. Found and mutation-verified in Batch KT-D (`failedProbeCount` 4 → 0 once the collector routes concurrently), then re-derived independently from source in review. **Resolution ruled 2026-09-01: retirement, not repair** — indirect probing is removed from BOTH libraries ([decision record](../superpowers/specs/2026-09-01-swim-slimdown-decision.md), [item](kt-retire-indirect-probing.md)): its classic purpose (containing a false verdict's spread) cannot occur here because membership is local (ADR-007), and the kt fleet ran without it unnoticed. The unguarded detector fields still get their monitor guard in the lifecycle batch — those races predate relaying. The once-untranslatable Dart relay scenario is obsolete. |
| Partition heal semantics | Dart's `TestNetwork.partition` UNREGISTERS the port and `heal` calls `reregister()`, so a "healed" node is really a re-registration — Dart's own KDoc concedes it "may need probe rounds to recover". kt (Batch KT-D) blocks links in place, leaving ports registered, so the node that rejoins is the same node with the same coordinator state. | kt | Dart should adopt block-in-place. It is the only shape in which "a partition heals" proves anything about recovery: Dart's own peer-status suite has to call `addPeer` on both sides after healing to stand in for a transport reconnection, which means it cannot prove heal-in-place recovery at all. |
| Congestion backpressure in tests | Dart's bus exposes `setSimulatedPendingCount`/`…ForPeer`, so a congestion test pins the gate against a DECLARED number. kt has no such knob — `pendingSendCount` can only be the link's real held-queue depth. | kt | A gate pinned against a declared number pins the test, not the production code. kt's congestion suite (Batch KT-D) pins the shipped gate at `GossipEngine.kt:229` for real, mutation-verified. | Reactive push on local append | Dart pushes new entries to reachable peers immediately (a `DeltaResponse` with no preceding `DeltaRequest`); kt is pull-only, so a post-start write waits for the next digest round. | Dart, on latency | Do NOT open a second home for this: the port is already carried by [Port the wire-efficiency behaviors to the Kotlin library](kt-port-wire-efficiency.md). | Simulated-clock dispatch | Dart's `TimePort.schedulePeriodic` takes a NON-suspending callback, so its fake clock fires boundaries synchronously in-line, never wedges, and propagates a callback throwable straight to the advancing caller. kt's takes `suspend () -> Unit` and originally AWAITED it, so a probe against an unresponsive peer deadlocked the advance that fired it.
